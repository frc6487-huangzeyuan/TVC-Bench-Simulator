# TVC Studio 0.1.0 · 飞控仿真实验室

双击本目录的 **TVC Studio.exe** 启动现代界面的本地仿真应用。也可以使用 `启动TVC Studio.cmd`。优先使用本机 Chrome，独立浏览器资料保存在 `work/chrome-profile/`。运行地址为 <http://127.0.0.1:8765>，仅监听本机。

## Studio 使用流程

1. 使用 `git submodule update --init --recursive` 初始化飞控子模块。打开“飞控工程”，选择 `firmware/TVC_Electronics` 并点击“读取工程”。已有工作区保留之前选择的工程路径；未初始化子模块时兼容原本机路径 `C:\Projects\代码\TVC_Electronics`。

2. 查看实际源码，点击“编译接入”。当前 TVC 适配器直接编译并调用 `Attitude.h`、`HistoryAttitude.h`、`GimbalControl.h` 等原工程代码，原文件不被修改。
3. 回到“仿真实验台”，设置初始机体倾角、PID、基准油门和其他工况。控制参数由界面传给算法，覆盖固件中的默认调参值。
4. 点击“开始实验”。可以暂停／继续、停止、施加持续 150ms 的外力扰动。三维台架、真实／估计姿态、执行器和 PID 曲线均来自运行中的物理与控制计算。
5. 在“测试记录”查看报告，导出 CSV。每次运行保存参数、随机种子、源码指纹和遥测，位于 `runs/<运行编号>/`。

已选择的本机工程路径保存在被 Git 忽略的 `work/studio_project.json`，不会随仓库分发。此前克隆如果已修改该文件，更新仓库前请先备份本机文件，以免 Git 拒绝更新。

右上角电源按钮用于关闭本地引擎；请先停止当前实验。关闭浏览器应用窗口不会强制结束后台引擎，重复启动 EXE 会复用现有引擎并打开界面。

当前为本机可运行的启动器，需要保留整个项目和 `.venv`，并使用本机的 MSYS2 C++ 编译器；不是一个可拷到任意电脑独立运行的安装包。

## 真实飞控与数据采集

进入“真实飞控”，直接在 Studio 界面连接、校准、切换 IMU、操作舵机和电调、配置 PID 与自动油门。会话、协议校验、命令排队、心跳和停止流程复用当前飞控工程 `web/dist` 中的原控制代码；原网页资源只读，若源码结构改变则明确报错。USB 串口使用 Chrome 的 Web Serial，选择飞控对应的端口；Wi-Fi 先连接 `TVC-Bench` 热点，再点击“连接 Wi-Fi”。本地引擎只转发到固件固定的 `192.168.4.1` 接口，并保留固件的会话令牌和单控制端机制。

设备连接并开始回传遥测后，点击“开始采集”；“结束采集”只结束本地记录。断开设备或离开真实飞控页面时，采集会结束，控制台仍执行其原有的断开与停止流程。记录位于 `real_runs/<采集编号>/`：`telemetry.jsonl` 保存每一帧完整遥测和本机接收时间，`metadata.json` 保存连接类型、设备身份和采集状态；可在页面导出 JSONL 或常用字段 CSV。CSV 的舵机角度和电调脉宽是设备报告的输出指令，不是舵机实际反馈或电机实测转速。真实数据与 `runs/` 下的仿真实验分开保存，不会自动作为仿真真值或训练样本。

姿态自动控制模式下，点击“开始姿态回中”后舵机即按实时姿态持续纠偏，电机仍可保持停止。电机启动前的纠偏预定位需要更新并重新上传飞控主控固件；旧固件不具备此启动门控，页面会拒绝自动模式电机启动。启动时主控根据最新校准姿态和 P 增益重新计算纠偏方位与俯仰，按限速发送舵机指令，电调保持停止脉宽；指令到达目标后再等待 `PREPOSITION_SETTLE_MS`，同时保持新鲜姿态。准备期间姿态变化过大、超时或故障会停止输出。等待时间只是估算：主控没有舵机实际位置反馈，无法确认机械到位；应按舵机实测速度调整时间并核对电调停止脉宽及方向。手动电机测试仍保持原有流程。

仓库中的 `firmware/TVC_Electronics` 子模块包含飞控源码和预定位改动，无需再次应用补丁；实验台实际使用的源码始终以“飞控工程”当前选择为准。`firmware/startup-preposition.patch` 是供旧版独立源码升级的历史补丁。子模块是独立 Git 工作区；更新飞控后，需在飞控仓库提交，再在仿真仓库提交新的子模块指针。已有外部飞控工程不会被覆盖，若同时使用两个工作区，请注意同步两边的提交。

## PID 与飞控参数调参（仅仿真）

实验台可选择“角度 PID”或“模型换算（实验）”。模型模式从当前质量、惯量、重心、推力及几何求竖直配平和小角度线性化 `q¨ = A q + B (v − bias)`，C++ 按 `v = bias + B⁻¹(u − A q)` 将 PID 的角加速度目标换算成二维纠偏角，再解算方位与俯仰舵角。推力仍作用于模型推力点，舵机限速、力矩和响应滞后照常计算。

- 模型模式 P/I/D 的输出单位为 °/s²，与普通 PID 不同，应单独调参；可点击“载入模型模式起始增益”（两轴 2.56 / 0.05 / 2）。目标角加速度上限为 15°/s²，物理最大修正角仍使用实验设置。调参器使用当前控制律，两种控制律的历史候选不能混用。
- 标定使用固定的 135° 机械分支、小角度和基准稳态推力；不追踪实际舵机位置，不实时辨识质量或推力，也不代表大角度下的完整逆动力学。物理参数改变会重新标定，初始姿态、噪声和扰动不会改变标定。配平不可达、零推力或效能矩阵近奇异时显式报错。
- 预定位通过可选的 `sim_preposition` 接口调用与运行阶段相同的 C++ 向量换算和逆运动学。旧控制器保留原 PID 行为；模型模式需要支持 `sim_set_model` 的新内核。
- 2026-10-29 固定物理参数、未参与初筛的种子 41029、24 个工况各 60 秒的对比：旧已调 PID 稳定 13/24、失稳 11；模型模式及其起始增益稳定 15/24、失稳 9，成本 153.04 → 125.53。5 个旧失败工况改善，但 3 个旧稳定工况退化。这是控制律及增益组合的对比，不能单独归因于模型换算；保持为实验选项，不能声称全工况稳定。

可复现命令（不改用户设置，输出文件必须尚不存在）：

```powershell
.\.venv\Scripts\python.exe tools\compare_control_laws.py --output reports\control-laws-new.json --seconds 60 --cases 24 --seed 41029
```

默认基线使用当前保存的增益；可用 `--baseline-gains 参数.json` 指定含六项增益或 `gains` 字段的 JSON。命令编译子模块源码；`--project` 可指定另一份兼容工程。参考 [PX4 控制分配的职责划分](https://github.com/PX4/PX4-user_guide/blob/main/en/concept/control_allocation.md)，具体配平、线性化及 C++ 换算为本项目实现，未移植 PX4 飞控。

模型系数只通过仿真扩展接口注入，不会写入真实设备。飞控库的 `GimbalModel` 默认禁用；实物启用需要独立的重心、推力、舵机方向和控制效能标定。

在“仿真实验台”设置初始姿态、舵机、PID 与模型参数后，进入“PID 与飞控调参”。优化与实验互斥；完成后可将候选参数载入仿真实验台，停止优化也会保留已评估的候选。载入不表示该候选已验证稳定。

- 默认使用差分进化 DE/rand/1/bin：初始种群包含当前基线，一部分在基线附近探索，一部分分层覆盖参数范围；之后每代进行变异、交叉和择优保留。可选同时搜索最大修正角（3–50°，与当前固定的 3° 积分上限兼容），机械限位和指令限速保持固定。不同参数归一化到同一搜索空间，随机种子可复现。所有候选使用相同工况和噪声种子，按失稳工况数、最差 10% 工况的平均得分、全体平均得分及稳定数依次排序。短回合优胜者再经过独立的完整时长筛选和最终验证；排序最优不一定平均得分最高。
- 可切换到原有 REINFORCE 作为对照。两种算法在相同的轮数、每轮候选数、初筛和验证工况设置下有相同候选评估预算；两者的候选分布和筛选排序不同，结果应以同工况独立验证为准，而非仅比较奖励曲线。

- REINFORCE 是有界高斯策略的单步回合 / 连续动作 bandit，原 C++ PID 始终承担闭环控制。它围绕当前 PID 对六个参数轮流进行成对局部探索，初始探索标准差为 0.08；学习的是固定增益，不是实时自适应 PID，也不是 PPO 或 DDPG。
- 默认 8 轮、每轮 6 组，每组在 16 个工况下各运行 10 秒。初筛后取最多 8 组候选及原参数，在 12 个新抽样工况和当前实验台原始工况上按完整实验时长筛选；最后在另外 24 个独立工况中比较原参数与筛选候选。REINFORCE 按稳定工况数、失稳工况数、失败工况平均坚持时间和得分排序；差分进化采用上面的鲁棒排序。如果候选使当前实验台工况由完整运行变为倒下、失去稳定，或比原参数明显更早倒下，则不予选用。训练初筛的最佳奖励与最终筛选结果可能来自不同参数。
- 可设置初始 X/Y 倾角、方位与俯仰舵机方向的范围，默认分别为 −5°～5°、−5°～5°、0°～360°、85°～185°。扰动力矩幅值默认最大为 0.003 N·m，可设为 0；方向、幅值、开始时间和持续时间在设定范围内变化。其余物理参数使用实验台快照并保持固定。训练、筛选和验证独立采样，同一工况的前后比较使用相同初始状态、噪声种子与扰动。有限抽样不能证明连续范围内所有工况都稳定。
- 新记录采用 0–100 分的单工况奖励：完整运行时为 `40 × exp(−平均倾角 / 10°) + 30 × exp(−最后 1 秒最大倾角 / 5°) + 20 × (1 − 输出受限比例) + 10 × exp(−PWM 总变化率 / 120 µs/s)`；提前失稳时为 `20 × 已运行时间比例 × exp(−实际运行期间平均倾角 / 90°)`，上限 20 分。多工况奖励是各工况得分均值，参数排序仍先看失稳等指标。原始成本仍完整记录：平均倾角 + 0.3 × 末态倾角 + 0.002 × PWM 总变化率 + 2 × 受限比例，加未稳定与失稳惩罚，供前后对比；控制器错误显式报告。旧记录保留原负成本奖励，不进行伪造换算。
- 奖励图默认展示相对原参数的得分变化，正值表示初筛平均得分提高；也可查看原始奖励。旧记录沿用当时的负成本奖励和含义。纵轴默认根据当前两条曲线的 10%–90% 分位数放大主要趋势，图中注明超出范围的回合数；可关闭放大查看完整范围，或筛选失稳回合，原始记录保持完整。结果页还提供同步双画面三维回放、时间拖动、不同验证工况选择，以及整体倾角、X/Y、实际方位和俯仰角曲线。训练前、候选均直接回放该次 MuJoCo 实际记录的姿态；一方提前失稳时，该模型停在最后真实帧。还可查看峰值、稳定时间、末态、受限比例及完整运行结果。

结果保存在 `tuning/<训练编号>/result.json`，姿态轨迹单独保存在同目录的 `comparison.json`。记录包含工况快照、源码指纹、种子、奖励历史、筛选和验证结果；可在“训练记录”切换最近 40 条结果并载入所选候选，训练进行中不能切换。历史训练没有三维轨迹时仍可查看原有曲线。重启引擎会恢复最近一次记录。模型和执行器尚未实物标定，仿真对比不证明实物稳定性。

差分进化参考 [SciPy 差分进化说明](https://docs.scipy.org/doc/scipy/reference/generated/scipy.optimize.differential_evolution.html)，采用 DE/rand/1/bin 和多工况字典序选择；REINFORCE 参考 [OpenAI Spinning Up 策略梯度文档](https://spinningup.openai.com/en/latest/spinningup/rl_intro3.html) 和[回合式 PID 调参研究](https://arxiv.org/abs/2112.15187)，未复现论文的 DPG 或稳定性保证。

## 释放前的箭体与舵机姿态

实验设置支持 `initial_x_deg` / `initial_y_deg`（机体初始倾角）、`initial_azimuth_deg`（方位舵机 0–360°，原中位 180°）和 `initial_elevation_deg`（俯仰舵机 85–185°，135° 为零偏转）。默认启用“开始前自动预定位舵机”：以上舵机角度是准备阶段开始时的位置。准备时固定两条台架轴、关闭推力和扰动，让舵机以原指令限速、速度与扭矩响应转向；TVC 控制器按初始倾角和 P 增益计算初始纠偏向量，按原控制器限幅选择较近的等效方位与对应俯仰角。纠偏向量小于 0.15° 时与原控制器一样保持方位、俯仰回中。自定义控制器没有已知的云台映射，仍预定位到机械中位。准备完成后释放台架、实验时间归零并启动控制器；关闭选项可从所填位置直接释放。预定位本身没有推力，释放后才随电机响应逐渐产生力矩；力矩大小、方向及能否稳定仍取决于模型参数和控制器。准备耗时与释放时的实际角度保存在实验记录中。强化学习的训练、筛选和前后验证使用同样的准备流程。

当前模型存在重心和推力点偏置，初始倾角很小时，比例修正产生的力矩可能不足以抵消这些偏置；该预定位不是全工况稳定保证。改变 PID、初始方位或模型参数后，应重新比较完整响应。

物理模型起步关节位置、首次输出 PWM 与 C++ 适配器的已发送指令同步初始化。适配器增加 `sim_set_initial_pwm()` 可选扩展，基础 ABI 仍为 v1；旧控制器没有该扩展时只接受原始 180° / 135° 起步位置。修改适配器后需重新编译当前 TVC 工程。原飞控源码、控制频率、指令限速、实际舵机响应及推力作用点保持原样。

方位舵机起步方向会影响可恢复范围。例如每周期 3 µs 限速对应约 54°/s，从中位转过 90° 约需 1.67 秒；原控制器大幅转向时会把俯仰收回中位，因此姿态可能在对准前就已失稳。初始方向必须与当前倾斜方向、增益和机械零位一起考虑，不能把一组起步配置视为所有方向都稳定。

## 控制代码接入范围

- **当前 TVC 工程**：运行原始姿态估计、缺帧历史预测、云台 PID 和限幅／限速逻辑；不模拟 ESP32 CPU 指令、FreeRTOS 完整任务调度、I2C/UART 寄存器、网页会话和网络状态机。
- **其他 C++ 工程**：根目录放置 `sim_controller.cpp`，实现 `controllers/sim_api.h` 中的 `sim_abi_version`、`sim_reset`、`sim_sample`、`sim_step`。可从界面“自定义控制器”开始，编辑后点击“保存并编译”。工作副本写入本项目 `controllers/custom/`，不会覆盖原飞控源码。
- 多个编译单元可在工程根目录的 `sim_project.json` 声明，例如 `{"sources":["src/control.cpp"],"include_dirs":["include"]}`。`sim_controller.cpp` 自动加入编译，不需要重复声明。
- 普通 `.ino` 可以读取与查看；需要硬件驱动的整套固件不能直接当作桌面控制器执行，必须通过上述明确接口接入。
- 接口 IMU 数据已经位于机体系：角速度为 °/s，加速度计为比力 g。默认通过原 C++ 姿态估计闭环；“直接使用真实姿态”仅用于隔离估计误差。自定义控制器可自行决定使用哪些输入，提供的 PD 参考例子明确使用真值。
- 控制器在独立进程运行。编译错误、运行返回错误、异常退出、长时间无响应都会在界面显示；异常退出也保留故障报告。源码发生变化后必须重新编译。

仿真物理频率 1000Hz，模拟 IMU 200Hz，控制循环 100Hz。推力在模型实际 `thrust_point` 位置沿风扇轴施加，云台由有速度／扭矩约束的响应模型驱动，作用于真实台架关节。这里没有直接把 PID 输出变成“理想恢复力矩”。

界面中的满油门推力、油门二次推力曲线、电机／舵机响应、扭矩、阻尼、噪声和延迟均是可调实验假设；尚未完成实物标定。仿真方位零位由几何建立为可调外参，实物安装方向仍需独立核对。

双击本目录的 **启动模型预览.cmd**。已配置本项目独立 Python 环境，无需启动 SolidWorks。

- 鼠标左键拖动：旋转视角；滚轮：缩放。
- 右侧 `Joint` 面板：调整四个关节。
- `1`：回到竖直状态；`2`：显示原 CAD 保存姿态；`3`：显示关节运动示例。
- `R`：开始／暂停重力运动。默认保持姿态，便于检查。这里是无控制器的刚体运动，不是姿态稳定演示。
- 关闭三维窗口退出。

## 运动结构

```text
base（固定外框）
└─ stand_outer（第一条被动轴承轴）→ outer_frame（内框）
   └─ stand_inner（第二条被动轴承轴）→ rocket_body（箭体）
      └─ tvc_azimuth（有限行程方位轴）→ azimuth_stage
         └─ tvc_elevation（俯仰轴）→ thrust_unit（电机、桨与支架）
```

从 101 个组件实例中提取了 80 个实体零件实例，合并为 5 个刚体；其余 21 个实例是装配层级，不重复计入网格和质量。两条台架轴取自顶层同心配合，云台轴取自电机组装中的同心配合。原 CAD 的两轴台架分别偏转约 7.90°、6.38°，风扇相对箭体另偏约 3.33°；URDF 零位已将箭体和推力轴回正，不改变源 CAD 保存姿态。

统一采用米、千克、秒、弧度。世界 Z 向上，坐标关系为 `(X,Y,Z)世界=(Y,-Z,-X)CAD`，世界原点位于固定底部型材下表面、台架轴交点的正下方。`body_reference` 的 Z 轴指向箭头，传感器轴和固件安装轴还需要在接算法时单独核对。

台架轴承轴按理想自由旋转处理，未臆造机械限位、摩擦和阻尼；TVC 方位行程为 ±180°，俯仰为 ±50°。54°/s、40.5°/s 来自现有固件 PWM 指令限速，并非实测舵机速度。方位机械零位仍需与实物校准；当前几何零位不能直接证明与 1500µs 中位完全一致。

配重／齿条机构按 CAD 保存位置并入箭体，不增加本次双轴台架任务之外的活动机构。没有启用自碰撞，URDF 未生成会填满框架空隙的包围盒碰撞体。

## 质量参数的依据和限制

用户确认箭体打印材料为 PETG、台架为铝型材。原 CAD 所有零件都未指定材料，原质量按默认 1000kg/m³ 计算；不能直接作为真实质量使用。

- 已识别的打印结构采用 PETG 标称密度 **1270kg/m³**，铝型材采用 **2700kg/m³**，按 CAD 实体体积重新计算质量和惯量。
- 打印结构的孔洞／薄壁以 CAD 几何为准，未模拟切片后的内部填充。`printed_cad_volume_factor=1.0` 表示按完整 CAD 实体估算，不代表实物 100% 填充。
- 电机、舵机、轴承、轴、金属舵盘等硬件仍保留 CAD 默认质量，清单中标为未核实。模型内也没有凭空加入电池、电调等缺少位置和质量的数据。
- 可在 `measured_part_mass_kg` 中按 `model_id` 填入实测单件质量；同型号重复实例会使用同一质量，惯量按 CAD 分布等比例修正。若实物内部质量分布与 CAD 不同，还需进一步修正惯量。
- 未提供真实舵机扭矩，URDF 的 `effort=0` 明确表示未标定，MJCF 尚未添加驱动执行器。预览通过关节坐标检查运动，不能据此宣称舵机带载能力足够。

因此目前适合核对几何、坐标、关节和搭建算法接口；可靠 PID 调参还需要实测整机／分组质量、重心、推力曲线和执行器响应。

## 验证与复现

已实际加载 URDF 和 MJCF，核对四个关节的独立运动、原始 CAD 保存姿态重建、竖直轴、惯量正定及 1 秒无控制重力积分的数值有限性。三种姿态已渲染并检查。

```powershell
.\.venv\Scripts\python.exe tools\build_model.py
.\.venv\Scripts\python.exe tools\validate_model.py
```

`tools/extract_cad.py` 仅用于从 SolidWorks 当前打开的总装配重新提取数据，不保存源文档。`tools/save_repaired_references.py` 是本次引用修复记录脚本，会先备份再保存，不需要重复运行。

后续接入控制时，在 `thrust_point` 施加沿真实风扇轴的推力，从理想 IMU 加入安装外参、噪声和延迟，然后复用原项目的 C++ 姿态估计和 GimbalPid。应先确认机体轴与实物零位，再接推力和舵机响应。
